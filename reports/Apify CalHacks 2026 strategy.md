# Ship CivicSignal to win both Apify prizes

**Build CivicSignal tonight.** It is a published, pay-per-event Apify Actor that reads local-government and school-board agendas from several platforms, normalizes them into one schema, and uses Claude to score each agenda item against a resident's plain-English interests. A Claude agent calls it through Apify's hosted MCP server and turns the results into cited alerts. The idea fits the Apify judging signals that the evidence supports. It is a custom Actor that fills a real Store gap: BoardDocs returns zero Store results, and the best "city council agenda" Actor has 16 users and 0 monthly actives ([Store API](https://api.apify.com/v2/store?search=boardDocs)). Apify is load-bearing in the product, not decorative. And it plays to Apify's 2026 push to make AI agents the platform's main customers (MCP, PPE pricing, x402, Apify AI). The same build qualifies for Anthropic's "Claude for Public Benefit" prize ($4,998 in value), Atlassian's Best Agent, and Cal Hacks' People-First Social Impact award with no extra engineering. Time is the binding constraint. At 9:30pm PDT on Oct 24 there are **about 11.5 hours until the 9:00am PDT Devpost deadline** ([Devpost](https://cal-hacks-13-0.devpost.com/)). The plan below therefore freezes features at 4:30am, keeps x402 and Standby as optional stretch goals, and spends the last four hours on the video, the Devpost writeup and rehearsal. Ranked alternatives follow for the case where the civic data sources fail the first-hour feasibility check: FundFit (grant matching, the safest), PriceLens (hospital prices, the most dramatic) and RecallRadar (product recalls, the simplest).

## Apify in 2026 is a tool layer that AI agents call and pay for

Apify calls itself "the largest marketplace of tools for AI," and its building block is the **Actor**. An Actor is a serverless, containerized program that takes JSON input and returns structured output. Each run gets its own dataset (append-only results, exportable as JSON, CSV or Excel), its own key-value store for blobs such as PDFs or screenshots, and its own request queue for crawl frontiers ([AGENTS.md](https://apify.com/AGENTS.md)). Billing is in compute units, where **1 CU = 1 GB of memory for 1 hour** ([AGENTS.md](https://apify.com/AGENTS.md)). Two Actor files matter most for judging. `.actor/input_schema.json` generates the Console form and also serves as the machine-readable tool signature that MCP clients and AI callers see ([input schema docs](https://docs.apify.com/platform/actors/development/actor-definition/input-schema)). **Standby mode** turns an Actor into a persistent HTTP server at a stable `https://<user>--<actor>.apify.actor` URL, and setting `webServerMcpPath` makes that Actor an MCP server in its own right ([Standby docs](https://docs.apify.com/platform/actors/development/programming-interface/standby)).

**The Store is huge and increasingly priced per event.** The public Store API reported **96,993 Actors on Oct 24, 2026** ([Store API](https://api.apify.com/v2/store?limit=1)). Apify's own blog copy still says "50,000+" in some places and "30,000+" in others ([MCP connectors blog](https://blog.apify.com/announcing-mcp-connectors/)). Rental pricing ended on **Sep 30, 2026**, and Actors that did not migrate to pay-per-event (PPE) now earn their creators nothing ([PPE migration blog](https://blog.apify.com/migrating-to-pay-per-event-pricing/)). Under PPE, the code charges for named events such as `Actor.charge('result')` ([PPE docs](https://docs.apify.com/platform/actors/publishing/monetize/pay-per-event)). Apify says it paid developers **$1.4M in a single month** in mid-2026 ([MCP connectors blog](https://blog.apify.com/announcing-mcp-connectors/)). Its $1M Challenge (Nov 2025–Jan 2026) drew 704 developers and 3,329 published Actors, and the jury judged on "monthly active users, Actor quality, technical excellence, and real-world usefulness" ([Apify challenge](https://apify.com/challenge)).

**Getting a first Actor deployed takes minutes.** The developer loop is `npm i -g apify-cli`, `apify login`, `apify create`, `apify run`, `apify push` ([AGENTS.md](https://apify.com/AGENTS.md)). The `apify` SDK builds Actors in JS/TS or Python, the `apify-client` libraries call them from apps, and both clients support a `maxTotalChargeUsd` spend cap. Crawlee is Apify's open-source crawling library. It offers Cheerio, Playwright and adaptive crawlers in JS, and BeautifulSoup, Parsel and Playwright crawlers in Python ([Crawlee](https://crawlee.dev)). Two 2026 additions matter for a team that builds with Claude Code. CLI 1.7/1.8 (July 2026) was rebuilt "for AI agents that mess up," with machine-readable status, input-schema hints and one-command MCP setup ([CLI blog](https://blog.apify.com/apify-cli-for-ai-agents/)). Apify Agent Skills (`npx skills add apify/agent-skills`) add `apify-actor-development` and `apify-actorization` skills that let a coding agent scaffold and deploy Actors ([Agent Skills docs](https://docs.apify.com/agents/skills)). Builds still take time and are capped at 4 GB and 1,800 seconds ([limits](https://docs.apify.com/platform/limits)), so push a hello-world build in the first hour.

**The agent stack is where Apify's attention is.** The hosted MCP server at `https://mcp.apify.com` speaks Streamable HTTP with OAuth or a bearer token. Its default tools are `search-actors`, `fetch-actor-details`, `call-actor`, the docs tools, `apify/rag-web-browser` and `apify/web-fetch`, and `?tools=` pins specific Actors ([MCP docs](https://docs.apify.com/platform/integrations/mcp)). Two limits shape any agent design. `call-actor` waits at most **45 seconds** and returns run and storage IDs, not the data itself. **Full-permission Actors are excluded** from MCP search and execution ([AGENTS.md](https://apify.com/AGENTS.md); [MCP docs](https://docs.apify.com/platform/integrations/mcp)). ## Store demand piles into social and maps while civic data sits empty

Usage is extremely concentrated. On Oct 24 the Google Maps scraper had **664,829 users and 44,951 monthly actives**, and `apify/rag-web-browser` had **33,486 monthly actives**, the clearest sign that "web data as a tool for LLM agents" is Apify's growth engine ([Store API](https://api.apify.com/v2/store?category=AI&sortBy=popularity)). Social, maps, jobs, Zillow and Reddit belong to entrenched maintainers, and Reddit also carries active litigation risk ([Proxyway](https://proxyway.com/news/reddit-sues-perplexity-oxylabs-two-more-web-data-providers)). Autonomous "do-anything" agent Actors attract almost no repeat use. Apify's own AI Web Agent has **6 monthly actives**, while the narrow `apify/ai-web-scraper` has 663 ([Store API](https://api.apify.com/v2/store?category=AGENTS&sortBy=popularity)). The lesson for Best Actor is to build a **narrow, reliable, agent-callable tool**, not a general agent.

Civic and public-interest data is the opposite: covered on paper, dead in practice. Legistar has a few tiny Actors built on its public web API, such as `talcoe/legistar-agendas` ([Apify Store](https://apify.com/talcoe/legistar-agendas)). One of them, `m_ctim/city-council-watch`, is marked "Under maintenance" ([Apify Store](https://apify.com/m_ctim/city-council-watch)). The top "city council agenda" result has 16 users and 0 monthly actives. School boards are effectively uncovered, and **BoardDocs returns zero results** ([Store API](https://api.apify.com/v2/store?search=school%20board); [Store API](https://api.apify.com/v2/store?search=boardDocs)). The open-source `civic-scraper` Python library already handles Civic Clerk, CivicPlus, Granicus, Legistar and PrimeGov, but it is not an Actor and does not support BoardDocs ([civic-scraper docs](https://civic-scraper.readthedocs.io/en/latest/usage.html)). Apify judges have rewarded this kind of work before: an FEC campaign-finance scraper won a weekly "Social Good" spotlight in the $1M Challenge ([Apify challenge](https://apify.com/challenge)). Government data is also hard in ways that justify an LLM layer. Data is fragmented across thousands of county systems, ASP.NET ViewState breaks naive requests, and status labels are never normalized ([Scrapfly](https://scrapfly.io/blog/posts/scraping-government-public-records-data)). An Actor that unifies platforms and adds AI relevance scoring is clearly better than the long tail it competes with. It is not a copy of anything on the Store.

### The custom Actor to build and publish

Publish it as **`civicsignal` ("Local Government Agenda Monitor")**, a Python Actor built from the `apify create` Python/BeautifulSoup template. Python fits because civic-scraper is Python. Plain HTTP plus BeautifulSoup keeps memory at 256–1,024 MB, which stretches the credits. The **input schema** takes `jurisdictions` (an array of `{platform, site}` objects with a prefilled Bay Area preset), `interests` (an array of plain-English strings), `sinceDays` (default 14), `minRelevance` (0–1, default 0.6), `maxMeetings`, and `includeFullText` (boolean). Every field gets a one-sentence description. The **dataset schema** emits one row per agenda item: `jurisdiction`, `platform`, `body` (for example "City Council" or "Board of Education"), `meetingDate`, `itemNumber`, `itemTitle`, `summary`, `actionType` (vote, public hearing, consent, informational), `relevanceScore`, `matchedInterest`, `reason`, `agendaUrl`, `pdfUrl`, `pdfPage`, and `publicCommentInfo`. Agenda PDFs go into the key-value store so citations resolve. **PPE pricing** charges two events, `agenda-item-scanned` (fractions of a cent) and `relevant-item-found` (a few cents). Exact prices are a judgment call; anchor them to x402's published example, where $1 buys roughly 250 Google Maps places ([x402 blog](https://blog.apify.com/introducing-x402-agentic-payments/)). Claude scoring runs on the creator's Anthropic key, stored as a secret Actor environment variable, and PPE pricing covers that cost. Keep default limited permissions, because full-permission Actors cannot be called through MCP ([MCP docs](https://docs.apify.com/platform/integrations/mcp)).

Platform coverage is the main feasibility risk. **In the first 30 minutes, check which platforms Berkeley, Oakland, San Francisco and Berkeley Unified actually use**, because the research did not verify this ([opportunity research](file:///home/taha/Code/hackathons/calhacks-2026/research_notes/Apify%20CalHacks%202026%20strategy/apify_opportunity_gaps.md)). Build the Legistar adapter first on its public web API. Then wrap one civic-scraper platform (Granicus, CivicPlus or PrimeGov), whichever a demo city uses. Add BoardDocs third, and only if a target school board runs on it. Three platforms is a strong pitch. Two working platforms with honest "roadmap" slides beat four flaky ones.

### Architecture

```
 Resident / student / reporter
        │  "Alert me about bike lanes + housing near campus"
        ▼
 Next.js app (Taha) ── Claude agent ──MCP──► mcp.apify.com?tools=<user>/civicsignal,apify/rag-web-browser
        │                                            │ call-actor (≤45 s) / get-dataset-items
        │                                            ▼
        │                        civicsignal Actor (Python, PPE, limited permissions)
        │                          ├─ adapters: Legistar API │ civic-scraper platform │ BoardDocs
        │                          ├─ PDF → agenda-item segmentation (pypdf)
        │                          ├─ Claude relevance scoring vs. interests (Matthew's rubric)
        │                          └─ outputs: dataset rows + PDFs in key-value store
        │                                            ▲
 Apify Schedule (hourly, per jurisdiction) ──────────┘   writes to a named "latest agendas" dataset
        │
 Apify webhook (run SUCCEEDED) ──► app endpoint ──► alert feed + Slack/email (stretch: MCP connector into Slack)
```

The **cache-first** design is the key engineering decision. Scheduled runs keep a named dataset of fresh, scored agenda items. The agent queries that cache for instant answers and calls `call-actor` live only for a new interest or jurisdiction, polling `get-actor-run` when a run exceeds 45 seconds ([AGENTS.md](https://apify.com/AGENTS.md)). This copies HomeMatch's lesson that Claude decides what context it needs ([Devpost](https://devpost.com/software/homematch-e35mgk)), and it keeps the live demo safe from slow municipal servers.

### Risks and mitigations

The largest risk is that **demo cities run on platforms the adapters don't cover**. The first-30-minute check handles it, and the fallback is to demo Legistar cities plus any civic-scraper platform that works. The second is **slow or blocking municipal servers** and cloud-IP blocks on government sites ([Scrapfly](https://scrapfly.io/blog/posts/scraping-government-public-records-data)). The cache-first design and a pre-warmed dataset mean the demo never depends on a live crawl. The third is the **45-second MCP timeout**: keep live runs to one jurisdiction and poll for anything longer. The fourth is **credit exhaustion**: use the Creator plan, HTTP crawlers and spend caps. The fifth is **Store publishing friction**. One unverified third-party guide claims a 2–5 day review ([Glama doc](https://glama.ai/mcp/servers/@roizenlabs/sportintel-mcp/blob/f8a45ddbbee2feb94796eb7a42efcac559a0b05b/docs/marketing/APIFY_STORE_SUBMISSION.md)), so publish by 03:00. If listing is delayed, the Actor page, its ID and the GitHub repo still prove it exists. Finally, a **judge may ask whether it duplicates civic-scraper**. The answer is that CivicSignal adds BoardDocs, a unified schema, LLM item-level relevance, PPE and agent access, none of which the library or any Store Actor offers.

## Conclusion

The evidence points to one reading of the Apify judges. They reward agents that treat Apify as a live tool, and a team that also ships a *good Actor*, meaning schemas, a README, PPE pricing and limited permissions, satisfies Best use of Apify and Best Actor with the same work. Past winners mostly called existing Store Actors, and only one published its own. At an event this size, a polished, published, MCP-callable Actor in an empty niche is the clearest way to stand above roughly a dozen precedents that set only the floor. The weakest link is not the idea but the clock. With about eleven hours left, the decisive moves are mechanical: push a build in the first hour, publish by 03:00, freeze at 04:30, and make the video show the Store page, a Console run and an outside agent calling the Actor, because Apify's judges may never see the live demo.

Two items remain uncertain and should be checked tonight rather than assumed. The first is whether one project may take both Apify prizes. The second is whether Store listing is instant. An x402 note conflicts on whether Standby Actors can be paid via x402 ([x402 docs](https://docs.apify.com/integrations/x402)), so keep CivicSignal in batch mode for the PPE/x402 story and treat Standby MCP as a pure stretch. If the Apify table answers any of these differently, adjust the Devpost framing, not the build.
